---

## 1. Постановка задачи

**Цель:** разработать детектор символов автомобильных номеров с точностью распознавания полного номера (Exact Match Accuracy) **не менее 80%**.

**Входные данные:**
- 593 кропа саудовских номерных знаков: train 563 / test 30 (456 `.jpeg` и 137 `.png`)
- Разметка на уровне **отдельных символов**: 27 классов (10 цифр + 17 букв)
- Формат аннотаций: Pascal VOC XML + YOLO TXT

**Метрики:**
- **Exact Match** - доля номеров, распознанных **полностью правильно** (все символы в правильном порядке), с 95% доверительным интервалом Уилсона;
- **CER** (Character Error Rate) - доля ошибочных символов относительно длины разметки.

## 2. Данные

Полный разведочный анализ с графиками - [reports/eda.md](reports/eda.md) (воспроизводится командой `make eda`). Выводы, которые определили пайплайн:

1. **PNG** - около 23% изображений; их нужно учитывать наравне с jpeg.
2. **Неполная разметка** - у 109 изображений train и 4 test меньше 7 боксов, хотя номер на картинке полный. Такие изображения исключаются из обучения и оценки (`src/data/quality.py`): остаётся 449 изображений train и 26 test.
3. **Повторы номеров** - 290 уникальных номеров на 563 изображения train (`5732NXD` - 40 раз), 23 из 30 номеров test есть в train. Train/val делится по номеру, а результат на test показывается отдельно для новых номеров.
4. **Дисбаланс классов** - цифры встречаются в разы чаще большинства букв; в test нет ни одного `T`.
5. **Размеры** - ширина от 52 до 2506 px; соотношение сторон около 2:1.

## 3. Подход

### 3.1. Кастомная архитектура FCOS

Реализована с нуля на PyTorch:
- **Backbone:** ResNet-18 (предобучен на ImageNet), `FrozenBatchNorm2d`
- **FPN (Feature Pyramid Network):** 3 уровня пирамиды со страйдами 8, 16, 32
- **FCOS Head:** anchor-free детектор с тремя ветвями (классификация, регрессия, centerness)
- **Назначение объектов:** точка позитивна на уровне пирамиды, отвечающем за размер объекта (`0-64`, `64-128`, `128+` px), как в статье FCOS
- **Регрессия:** `exp(scale · x) · stride` от центров ячеек
- **Loss:** Focal Loss + GIoU Loss + BCE для centerness
- **Оптимизатор:** AdamW с warmup + cosine annealing, gradient clipping
- **Выбор чекпоинта:** по Exact Match на val

### 3.2. YOLOv8

Основная модель - YOLOv8m (25.8M параметров), гиперпараметры в `configs/yolo_train.yaml`: 100 эпох, `imgsz=640`, `patience=25`, `seed=42`, без горизонтальных отражений (`fliplr: 0`).

### 3.3. Аугментация

Offline-аугментация train ×4 (`augment_data.py`, 355 → 1420 изображений): Affine (±5°, ±10% масштаб), MotionBlur, GaussianBlur, RandomBrightnessContrast, HueSaturationValue, GaussNoise, ISONoise. Без отражений и без CoarseDropout, который мог целиком закрыть символ при сохранённой метке.

### 3.4. Постобработка

Геометрический фильтр общий для YOLO и FCOS (`src/evaluation/postprocess.py`): символы номера одной высоты и на одной линии, поэтому детекции с выбросами по высоте или по вертикали отбрасываются, а из оставшихся берутся до 7 самых уверенных.

## 4. История экспериментов (старый протокол)

Первые эксперименты дали такие результаты:

| Модель | Обучающая выборка | mAP50 (val) | Exact Match (test) |
|---|---|---|---|
| FCOS | 349 изображений | ~60% | ~20% |
| FCOS | 1381 изображение (аугментация) | - | 65% |
| YOLOv8s | 349 изображений | 96.9% | 75% (15/20) |
| YOLOv8m | 1381 изображение (аугментация) | 98.2% | 85% (17/20) |

**Эти цифры недействительны** и не должны использоваться для сравнения моделей:

1. **Test урезан с 30 до 20 изображений** - скрипты искали только `*.jpeg`, PNG выпадали (и из train тоже: 349 вместо 450 изображений).
2. **В test были изображения с неполной разметкой** (`JB`, `927JJ`, `8883`): модель, которая правильно читает номер целиком, получала на них «ошибку».
3. **Утечка:** 15 из 20 оцениваемых номеров test встречаются в train, часть кадров почти идентична; val при случайном разбиении по изображениям тоже пересекался с train по номерам, поэтому mAP50 на val 96.9-98.2% завышен.
4. **Порог уверенности и параметры фильтра подбирались на test.**
5. **Мало данных для вывода:** 95% доверительный интервал для 17/20 - [64%; 95%], разница 75% → 85% - это 2 изображения.
6. **YOLO обучалась с `fliplr=0.5`** - половина примеров содержала зеркальные символы с исходными метками.
7. **mAP50 FCOS** (~60%) не считался кодом - это оценка, а не измерение.

### Разбор ошибок YOLOv8m

Из трёх «ошибок» YOLOv8m на 20 изображениях test две - ошибки разметки, а не модели:

| Разметка | Предсказание | На изображении | Чья ошибка |
|---|---|---|---|
| `2948URD` | `298URD` | `2948 URD` | модель: пропущена `4` |
| `JB` | `3324RJB` | `3324 RJB` | разметка: размечены 2 символа из 7 |
| `927JJ` | `6927NJJ` | номер из 7 символов | разметка: размечены 5 символов из 7 |

На 17 изображениях с полной разметкой модель ошиблась один раз (16/17), но и эта цифра не годится как оценка из-за утечки и подбора порога на test.

## 5. Что исправлено в пайплайне

| Проблема | Исправление |
|---|---|
| PNG не учитывались | `src/data/images.py`: `.jpeg`, `.jpg`, `.png` во всех скриптах |
| Неполная разметка | `src/data/quality.py`: в обучение и оценку берутся только номера из 7 символов без вырожденных боксов |
| Утечка train/val, `split_data.py` перемещал исходные файлы | Деление по номеру, списки в `splits/`, исходные данные не изменяются |
| Аугментация молча теряла изображения и портила метки | `clip=True` вместо `try/except`, без CoarseDropout, seed |
| Отражения при обучении YOLO, обучение без конфига | `configs/yolo_train.yaml`: `fliplr: 0`, `seed: 42`; `data.yaml` генерируется |
| Подбор порога на test, нет доверительного интервала | `evaluate.py`: порог подбирается на val, Exact Match с 95% ДИ и CER, отдельно для новых номеров |
| Дефекты FCOS | Назначение по уровням FPN, регрессия `exp(scale · x) · stride`, центры ячеек, `FrozenBatchNorm2d`, выбор чекпоинта по Exact Match |

## 6. Результаты по новому пайплайну

### 6.1. YOLOv8m

Обучение по `configs/yolo_train.yaml` на GTX 1660 Ti (6 GB): `amp=False` (на GTX 16xx с AMP loss уходит в `nan`) и `batch=4` (эффективный батч не меняется - Ultralytics накапливает градиенты до 64). Early stopping на 91-й эпохе, лучшая - 66-я (mAP50 0.993, mAP50-95 0.775 на val).

![Обучение YOLOv8m](reports/final/03_yolov8m_training.png)

Порог уверенности подбирался на val (0.15 / 0.25 / 0.4 / 0.5) - результат от него не зависит, выбран 0.25. Test запускался один раз:

| Выборка | Изображений | Exact Match | 95% ДИ | CER |
|---|---|---|---|---|
| val (номеров нет в train) | 94 | 91.5% (86/94) | [84.1%; 95.6%] | 1.8% |
| test, все | 26 | 96.2% (25/26) | [81.1%; 99.3%] | 0.5% |
| test, номер есть в train | 20 | 95.0% (19/20) | [76.4%; 99.1%] | 0.7% |
| test, новый номер | 6 | 100% (6/6) | [61.0%; 100%] | 0.0% |

Цель 80% Exact Match достигнута. Главная оценка - val: на test доверительный интервал шириной около 18 п.п., а новых номеров всего 6.

![Примеры предсказаний](reports/final/06_prediction_examples.png)

#### Разбор ошибок

Единственная ошибка на test: `3757JED` → `3757JDD`, кроп сильно размыт.

Ошибки на val (8 из 94):

| Разметка | Предсказание | Причина |
|---|---|---|
| `1110SVA` | `1110S` | геометрический фильтр: длинный однострочный номер, буквы крупнее цифр и выше них |
| `2260GVJ` | `2260` | то же; без фильтра оба номера читаются верно |
| `3577LUJ` | `3575BUJ` | кроп около 100 px в ширину |
| `8454BKJ` | `9454BKJ` | мелкий кроп |
| `2807ZVB` | `9807ZVB` | мелкий кроп, тёмный фон |
| `1000LHA` | `0000LHA` | мелкий кроп |
| `2583NLB` | `2583LLB` | нижняя строка стёрта (2 кадра одного номера) |

Две ошибки из восьми исправимы постобработкой; остальные - мелкие и плохо читаемые кропы, где помогло бы обучение с большим `imgsz` или второй этап распознавания по кропам символов.

### 6.2. FCOS

Обучение `make train-fcos`: 60 эпох, batch 4, 1420 аугментированных изображений, около 1 ч на GTX 1660 Ti. NaN не было. Чекпоинт выбирается по Exact Match на val - лучшая 20-я эпоха (90.4%), дальше значение держится в районе 80-88%: одно изображение val - это 1.1 п.п., поэтому выбор эпохи шумный.

![Обучение FCOS](reports/final/04_fcos_training.png)

Подбор порога на val:

| conf | 0.2 | 0.3 | 0.4 | 0.5 |
|---|---|---|---|---|
| Exact Match (val) | 89.4% | **90.4%** | 88.3% | 85.1% |

Test (один прогон, conf 0.3):

| Выборка | Изображений | Exact Match | 95% ДИ | CER |
|---|---|---|---|---|
| val (номеров нет в train) | 94 | 90.4% (85/94) | [82.8%; 94.9%] | 2.4% |
| test, все | 26 | 88.5% (23/26) | [71.0%; 96.0%] | 1.6% |
| test, номер есть в train | 20 | 90.0% (18/20) | [69.9%; 97.2%] | 1.4% |
| test, новый номер | 6 | 83.3% (5/6) | [43.6%; 97.0%] | 2.4% |

Цифра на val завышена: по ней выбирались и чекпоинт, и порог.

Ошибки на test - подстановки букв: `2948URD` → `2948URB`, `7980ESJ` → `7980SSJ`, `3523AHA` → `3523AAA`. На val (9 из 94) большая часть ошибок те же, что у YOLOv8m: мелкие кропы (`3577LUJ`, `8454BKJ`, `2807ZVB`), стёртый `2583NLB` и `2260GVJ`, где геометрический фильтр отбрасывает буквы. Свои ошибки FCOS - `6134GLD` → `6734GLD`, нечитаемый `7997EBS` и два кадра `1110SVA`.

### 6.3. Сравнение

| | YOLOv8m | FCOS |
|---|---|---|
| Exact Match, val | 91.5% | 90.4% |
| Exact Match, test | 96.2% (25/26) | 88.5% (23/26) |
| CER, test | 0.5% | 1.6% |
| Обучение на GTX 1660 Ti | ~3.8 ч | ~1 ч |

Обе модели проходят цель 80%. YOLOv8m точнее на test (разница - 2 изображения, интервалы сильно пересекаются) и не требует выбора чекпоинта по val, поэтому остаётся основной моделью. FCOS обучается почти в 4 раза быстрее.

## 7. Команды для воспроизведения

```bash
make install                                    # зависимости
make eda                                        # разведочный анализ
make data                                       # yolo_dataset по splits/ + аугментация
make train-yolo                                 # YOLOv8m по configs/yolo_train.yaml
make eval-yolo SPLIT=val CONF="0.15 0.25 0.4"   # подбор порога на val
make eval-yolo SPLIT=test CONF=0.25             # финальная оценка
make train-fcos                                 # FCOS
make eval-fcos SPLIT=val CONF="0.2 0.3 0.4"     # подбор порога FCOS на val
make eval-fcos SPLIT=test CONF=0.3              # финальная оценка FCOS
make report                                     # графики в reports/final
```

## 8. Направления развития

1. **Геометрический фильтр** для длинных однострочных номеров.
2. **Доразметка** изображений с неполной разметкой вместо их исключения.
3. **Независимый test** из номеров, которых нет в train.
4. **Двухэтапный пайплайн:** YOLO детектирует символы → CRNN/SVTR распознаёт каждый кроп.
5. **Контекстная постобработка:** формат номера `DDDDLLL` - позиции 1-4 только цифры, 5-7 только буквы.
