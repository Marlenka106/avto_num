**Среда разработки:** Ubuntu 24.04 + VS Code; CI - Python 3.10, обучение - Python 3.12  
**GPU обучения:** NVIDIA GeForce GTX 1660 Ti (6 GB VRAM)

---

## 1. Постановка задачи

**Цель:** разработать детектор символов автомобильных номеров с точностью распознавания полного номера (Exact Match Accuracy) **не менее 80%**.

**Входные данные:**
- 593 кропа саудовских номерных знаков: train 563 / test 30 (456 `.jpeg` и 137 `.png`)
- Разметка на уровне **отдельных символов**: 27 классов (10 цифр + 17 букв)
- Формат аннотаций: Pascal VOC XML + YOLO TXT

**Метрики:**
- **Exact Match** - доля номеров, распознанных **полностью правильно** (все символы в правильном порядке), с 95% доверительным интервалом Уилсона;
- **CER** (Character Error Rate) - доля ошибочных символов относительно длины разметки.

## 2. Данные

Полный разведочный анализ с графиками - [reports/eda.md](reports/eda.md) (воспроизводится командой `make eda`). Выводы, которые определили пайплайн:

1. **PNG** - около 23% изображений; их нужно учитывать наравне с jpeg.
2. **Неполная разметка** - у 109 изображений train и 4 test меньше 7 боксов, хотя номер на картинке полный. Такие изображения исключаются из обучения и оценки (`src/data/quality.py`): остаётся 449 изображений train и 26 test.
3. **Ошибки в символах** - `.xml` и `.txt` согласованы, но у 4 изображений train один символ размечен неверно. Исправляется при чтении (`LABEL_FIXES`), иначе кадры одного автомобиля попадают и в train, и в val.
4. **Повторы номеров** - 286 уникальных номеров на 563 изображения train (`5732NXD` - 40 раз), 23 из 30 номеров test есть в train. Train/val делится по номеру, номера с больше чем 5 кадрами (7 номеров) - только в train, чтобы один номер не занимал половину val; результат на test показывается отдельно для новых номеров.
5. **Дисбаланс классов** - цифры встречаются в разы чаще большинства букв; в test нет ни одного `T`.
6. **Размеры** - ширина от 52 до 2506 px; соотношение сторон около 2:1.

## 3. Подход

### 3.1. Кастомная архитектура FCOS

Реализована с нуля на PyTorch:
- **Backbone:** ResNet-18 (предобучен на ImageNet), `FrozenBatchNorm2d`
- **FPN (Feature Pyramid Network):** 3 уровня пирамиды со страйдами 8, 16, 32
- **FCOS Head:** anchor-free детектор с тремя ветвями (классификация, регрессия, centerness)
- **Назначение объектов:** точка позитивна на уровне пирамиды, отвечающем за размер объекта (`0-64`, `64-128`, `128+` px), как в статье FCOS
- **Регрессия:** `exp(scale · x) · stride` от центров ячеек
- **Loss:** Focal Loss + GIoU Loss + BCE для centerness
- **Оптимизатор:** AdamW с warmup + cosine annealing, gradient clipping
- **Выбор чекпоинта:** по Exact Match на val

### 3.2. YOLOv8

Основная модель - YOLOv8m (25.8M параметров), гиперпараметры и все аугментации в `configs/yolo_train.yaml`: 100 эпох, `imgsz=640`, `patience=25`, `seed=42`, без горизонтальных отражений (`fliplr: 0`).

Почему детектор символов, а не распознавание строки целиком (CRNN, PARSeq):

- задание - разработать детектор, а разметка датасета - рамки отдельных символов; детектор использует её полностью;
- ошибка видна на уровне символа: какой символ пропущен или перепутан и где он на кропе;
- символы на номере не перекрываются и стоят в одну строку, поэтому строка собирается сортировкой рамок слева направо.

Почему YOLOv8, а не только своя FCOS: зрелая реализация с встроенными mAP, логами обучения и онлайн-аугментациями, которая служит опорной моделью для своей FCOS. Размер `m` выбран без сравнения с `s` по новому протоколу - такое сравнение не проводилось (около 4 ч обучения на каждый вариант).

### 3.3. Аугментация

Offline-аугментация train ×4 (`augment_data.py`, 357 → 1428 изображений): Affine (±5°, ±10% масштаб), MotionBlur, GaussianBlur, RandomBrightnessContrast, HueSaturationValue, GaussNoise, ISONoise. Без отражений и без CoarseDropout, который мог целиком закрыть символ при сохранённой метке.

### 3.4. Постобработка

Геометрический фильтр общий для YOLO и FCOS (`src/evaluation/postprocess.py`): символы номера одной высоты и на одной линии, поэтому детекции с выбросами по высоте или по линии отбрасываются, а из оставшихся берутся до 7 самых уверенных. Линия - прямая через центры символов (оценка Тейла-Сена, устойчива к отдельным ложным детекциям): кропы часто наклонены, и прежний фильтр по горизонтали отбрасывал правильные символы.

Проверка фильтра на разметке (рамки из `.txt` вместо предсказаний): прежний фильтр терял символы у 12 из 475 изображений с полной разметкой - все 12 наклонённые номера, новый не теряет ни одного. У YOLO NMS выполняется без учёта класса: при NMS по классам две гипотезы одного символа (например, `B` и `8`) оставались обе и могли попасть в строку. Оценку без фильтра даёт `evaluate.py --no-filter`.

## 4. История экспериментов (старый протокол)

Первые эксперименты дали такие результаты:

| Модель | Обучающая выборка | mAP50 (val) | Exact Match (test) |
|---|---|---|---|
| FCOS | 349 изображений | ~60% | ~20% |
| FCOS | 1381 изображение (аугментация) | - | 65% |
| YOLOv8s | 349 изображений | 96.9% | 75% (15/20) |
| YOLOv8m | 1381 изображение (аугментация) | 98.2% | 85% (17/20) |

**Эти цифры недействительны** и не должны использоваться для сравнения моделей:

1. **Test урезан с 30 до 20 изображений** - скрипты искали только `*.jpeg`, PNG выпадали (и из train тоже: 349 вместо 450 изображений).
2. **В test были изображения с неполной разметкой** (`JB`, `927JJ`, `8883`): модель, которая правильно читает номер целиком, получала на них «ошибку».
3. **Утечка:** 15 из 20 оцениваемых номеров test встречаются в train, часть кадров почти идентична; val при случайном разбиении по изображениям тоже пересекался с train по номерам, поэтому mAP50 на val 96.9-98.2% завышен.
4. **Порог уверенности и параметры фильтра подбирались на test.**
5. **Мало данных для вывода:** 95% доверительный интервал для 17/20 - [64%; 95%], разница 75% → 85% - это 2 изображения.
6. **YOLO обучалась с `fliplr=0.5`** - половина примеров содержала зеркальные символы с исходными метками.
7. **mAP50 FCOS** (~60%) не считался кодом - это оценка, а не измерение.

## 6. Результаты по новому пайплайну

### 6.1. YOLOv8m

Обучение по `configs/yolo_train.yaml` на GTX 1660 Ti (6 GB): `amp=False` (на GTX 16xx с AMP loss уходит в `nan`) и `batch=4` (эффективный батч не меняется - Ultralytics накапливает градиенты до 64). Прошли все 100 эпох (около 4.3 ч): метрики на val росли до конца, early stopping не сработал. Лучшая - 99-я эпоха (mAP50 0.995, mAP50-95 0.822 на val), последние 10 эпох без mosaic добавили около 0.003 mAP50-95.

![Обучение YOLOv8m](reports/final/03_yolov8m_training.png)

Порог уверенности подбирался на val (0.15 / 0.25 / 0.4) - результат от него не зависит, выбран 0.25. Test запускался один раз:

| Выборка | Изображений | Exact Match | 95% ДИ | CER |
|---|---|---|---|---|
| val (номеров нет в train) | 92 | 96.7% (89/92) | [90.8%; 98.9%] | 0.5% |
| test, все | 26 | 100% (26/26) | [87.1%; 100%] | 0.0% |
| test, номер есть в train | 20 | 100% (20/20) | [83.9%; 100%] | 0.0% |
| test, новый номер | 6 | 100% (6/6) | [61.0%; 100%] | 0.0% |

Exact Match по номерам (каждый номер с одинаковым весом): val 94.4% (45 номеров), test 100% (22 номера). Цель 80% Exact Match достигнута. Главная оценка - val: на test 26 изображений и только 6 новых номеров, нижняя граница интервала - 87%.

![Примеры предсказаний](reports/final/06_prediction_examples.png)

#### Разбор ошибок

На test ошибок нет. Ошибки на val (3 из 92):

| Разметка | Предсказание | Кроп |
|---|---|---|
| `4875UTA` | `4875UTB` | 572 px, сильно размыт |
| `7295GNJ` | `7295ENJ` | 99 px, размыт |
| `9022ALB` | `9022LB` | 74 px, буква `A` не найдена |

Все три - плохо читаемые кропы, а не дефекты постобработки. Геометрический фильтр на val и test только исправляет ошибки: без него Exact Match на val 94.6% (87/92), на test 96.2% (25/26). Без фильтра в строку попадают лишние детекции вне линии символов: `7980ESJ` → `7980ESJX` и `7980ESJB` на val, `5578KGA` → `9575708KGA` на test.

### 6.2. FCOS

Обучение `make train-fcos`: 60 эпох, batch 4, 1428 аугментированных изображений, около 1 ч на GTX 1660 Ti. NaN не было. Чекпоинт выбирается по Exact Match на val - лучшая 43-я эпоха (91.3%); после 20-й эпохи значение колеблется от 77% до 91%: одно изображение val - это 1.1 п.п., поэтому выбор эпохи шумный.

![Обучение FCOS](reports/final/04_fcos_training.png)

Порог на val (0.2 / 0.3 / 0.4) на результат не влияет, оставлен 0.3. Test (один прогон):

| Выборка | Изображений | Exact Match | 95% ДИ | CER |
|---|---|---|---|---|
| val (номеров нет в train) | 92 | 91.3% (84/92) | [83.8%; 95.5%] | 1.9% |
| test, все | 26 | 88.5% (23/26) | [71.0%; 96.0%] | 2.2% |
| test, номер есть в train | 20 | 100% (20/20) | [83.9%; 100%] | 0.0% |
| test, новый номер | 6 | 50.0% (3/6) | [18.8%; 81.2%] | 9.5% |

Цифра на val завышена: по ней выбирался чекпоинт. Все три ошибки на test - на новых номерах и мелких кропах (84-129 px): `7980ESJ` → `7980EGJ`, `2146EKA` → `2146SKA`, `3523AHA` → `3523TH3`. На 6 новых номерах интервал от 19% до 81% - по этой подвыборке модели не сравнить.

На val 8 ошибок из 92, большая часть - подстановки похожих букв на мелких кропах (63-175 px): `G` → `B`, `R` → `B`, `G` → `S`, `9` → `8`. Две общие с YOLOv8m (`7295GNJ`, `9022ALB`). Свои ошибки FCOS на чётких крупных кропах: `3754VLJ` → `3754VVJ` и `7279AAA` → `2243AAA` - на этих изображениях YOLOv8m не ошибается. Фильтр у FCOS исправляет одну ошибку на val (90.2% без него), на test ничего не меняет.

### 6.3. Сравнение

| | YOLOv8m | FCOS |
|---|---|---|
| Exact Match, val | 96.7% | 91.3% |
| Exact Match по номерам, val | 94.4% | 89.5% |
| Exact Match, test | 100% (26/26) | 88.5% (23/26) |

Обе модели проходят цель 80%. YOLOv8m точнее и на val (разница - 5 изображений, интервалы пересекаются), и на test, и не требует выбора чекпоинта по val, поэтому остаётся основной моделью. FCOS обучается в 4 раза быстрее, но чаще путает похожие буквы.

## 7. Границы применимости

- **Вход - уже вырезанный кроп одного номера.** На фото автомобиля целиком модель ищет символы по всему кадру; для такого входа нужен первый этап - детекция номерного знака, а в датасете нет ни фото автомобилей, ни разметки номеров.
- **Саудовский однострочный номер.** Распознаются 27 латинских символов нижней строки, арабские не распознаются. Строка собирается слева направо - двухстрочных номеров в датасете нет, и на них сборка не рассчитана.
- **До 7 символов.** Фильтр оставляет 7 самых уверенных символов. Короткие номера бывают (`641BBB`), но в данных редки и вместе с неполной разметкой исключены из оценки - точность на них не измерена.
- **Качество кропа.** Основные ошибки - кропы около 100 px в ширину, размытые и стёртые. Наклон номера учитывается фильтром, сильная перспектива отдельно не проверялась.
- **Оценка.** В test 26 изображений с полной разметкой и только 6 новых номеров, доверительный интервал на test - 13-25 п.п., на новых номерах - около 40-60 п.п. Все данные из одного источника (Labelbox), обобщение на другие камеры и страны не проверялось.

## 8. Команды для воспроизведения

```bash
make install                                    # зависимости
make eda                                        # разведочный анализ
make data                                       # yolo_dataset по splits/ + аугментация
make train-yolo                                 # YOLOv8m по configs/yolo_train.yaml

make eval-yolo SPLIT=test CONF=0.25             # финальная оценка

make eval-fcos SPLIT=val CONF="0.2 0.3 0.4"     # подбор порога FCOS на val
make eval-fcos SPLIT=test CONF=0.3              # финальная оценка FCOS
make report                                     # графики в reports/final
make demo                                       # распознавание номеров на number_plates/test
```

## 9. Направления развития

1. **Доразметка** изображений с неполной разметкой вместо их исключения.
2. **Независимый test** из номеров, которых нет в train.
3. **Двухэтапный пайплайн:** YOLO детектирует символы → CRNN/SVTR распознаёт каждый кроп.
4. **Контекстная постобработка:** формат номера `DDDDLLL` - позиции 1-4 только цифры, 5-7 только буквы.
